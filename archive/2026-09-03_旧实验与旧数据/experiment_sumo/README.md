# Sidewalk Robot Quota Experiment

A pedestrian-priority **road-quota algorithm** for delivery robots on
sidewalks: given only **pedestrian flow `q_p`** and **effective sidewalk width
`W`**, output the maximum admissible **delivery-robot flow `q_r*`** that keeps
pedestrian service acceptable.

This is the reproducible experiment behind the research direction
*"How Many Delivery Robots Can a Sidewalk Handle?"* — see the two Markdown
documents in the parent directory for the full research framing and the
experiment plan.

## Method (summary)

1. **Simulator** (`scripts/simulator.py`): a microscopic 2-D social-force
   model (Helbing & Molnár 1995) for pedestrians on a straight sidewalk cell,
   plus a fixed **reference delivery robot** (AIDEN-style footprint, 5 km/h
   nominal speed) acting as a moving capacity proxy with longitudinal
   collision-free control and lateral yield.  Pedestrian free-flow speed is
   calibrated to the Singapore mean walking speed of ~1.25 m/s.
2. **Ground truth** (`scripts/ground_truth.py`): pedestrian-only baseline per
   `(W, q_p)` cell, then a robot-flow sweep `q_r ∈ {0..10}` over 30 seeds each.
   A flow is *admissible* iff the **mean** pedestrian-service constraints hold
   (plan section 5.1): (a) speed retention `R̄_v ≥ 0.90`, (b) flow stability
   `q̄_out/q̄_in ≥ 0.90`, (c) density floor `ρ̄ ≤ 1.2 ped/m²`.  `q_r*` is the
   largest admissible flow.  (The per-seed `Pr(C_p=1) ≥ 0.95` fraction is also
   reported but, at low `q_p`, it is dominated by arrival-count noise, so the
   mean is the primary criterion.)
3. **Quota algorithm** (`scripts/fit_quota.py`): `Model A` (width-normalized
   power law `q_hat_r = W·c·(q_p/W)^p`), `Model B` (2-D power surface), and a
   non-parametric isotonic baseline.  Two hard-zero rules are applied:
   over-capacity cells (`q_p/W ≥ x_crit`) and cells narrower than the minimum
   robot-operable width (`W < W_min`).
4. **Validation** (`scripts/validate.py`): held-out unseen-width cells for
   MAE / RMSE / over-allocation / OAR, plus the closed-loop **Service Violation
   Rate** (re-simulate the predicted quota and check `C_p`).
5. **Sensitivity** (`scripts/sensitivity.py`): speed-retention threshold
   {5,10,15%} and reference-robot speed {0.8,1.0,1.2}×.

## Reproduce

```powershell
cd experiment
pip install numpy scipy matplotlib pandas
python scripts/run_all.py --n-procs 16
```

`run_all.py` runs every stage in order and writes all CSVs / figures / model
files.  Each stage can also be run standalone (see the module docstrings).

## Honest scope notes

- The **simulation engine is a Python social-force reimplementation**, not the
  SUMO–JuPedSim binary (SUMO is not available in this environment).  The
  experimental *methodology* (baseline → sweep → `q_r*` → algorithm → held-out
  + closed-loop validation) follows the plan exactly; the pedestrian-dynamics
  kernel is a documented stand-in that can be swapped for SUMO–JuPedSim later.
- **Field geometry / counts** (the plan's Phase 1–2) were not available, so the
  "Singapore cells" are represented by the realistic effective-width range
  1.5–3.0 m and demand range 10–60 ped/min rather than surveyed Bendemeer Road
  measurements.  This is stated explicitly in the report.
- All numbers in `outputs/` are **real** — generated by running the code above,
  not fabricated.
